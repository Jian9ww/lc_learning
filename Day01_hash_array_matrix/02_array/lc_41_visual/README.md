# LC41 缺失的第一个正数：讲解

题目：找出数组里没有出现的最小正整数，要求时间 O(n)、额外空间 O(1)。例：`[3,4,-1,1]` → 2，`[1,2,0]` → 3，`[7,8,9,11,12]` → 1。

## 1. 原始解法在做什么

```cpp
mp[cur_num] = cur_num + 1;              // 记下每个出现过的正数
...
if(mp.find(v) == mp.end()){ //当前num + 1不在
    if(k <= result) result = k + 1;
}
```

思路是：答案的前一个数一定出现过（答案是 1 时除外）。所以先记下所有正数，再找“k 出现了、k + 1 没出现”的位置，取最小的 k + 1；1 没出现时答案直接是 1。这和 LC128 “没有 x − 1 才是起点”是同一种想法，只是换成了看右边。

这个思路是对的：和暴力解法对拍 20 万组随机数据，结果全部一致。三点说明：

- **超出要求的是空间，不是时间。** 哈希表让时间保持在平均 O(n)，但它本身占 O(n) 的额外空间，题目要求 O(1)。
- **`cur_num + 1` 会溢出。** LeetCode 原题允许 `nums[i]` 取到 2³¹ − 1，这时加 1 超出 `int` 范围（见 note B.1）。实测输入 `[2147483647]` 返回 −2147483648，正确答案是 1。
- **值是多余的。** 表里存的 `x + 1` 可以由键算出来，用 `unordered_set` 记“出现过”就够了（note E.2）。

## 2. 关键观察：答案只可能是 1 到 n + 1（动画第 2 章）

数组有 n 个数，最多把 1、2、……、n 全部占满。

- 占满了：答案是 n + 1。
- 没占满：1 到 n 里有缺的，答案是缺的里面最小的那个。

所以 ≤ 0 的数和 > n 的数都不影响答案，只需要知道 **1 到 n 每个数有没有出现**。

## 3. 过渡版：用一个标记数组

知道了范围，就不需要哈希表，开一个长度 n + 1 的数组记“出现过没有”即可：

```cpp
int n = nums.size();
vector<bool> seen(n + 1, false);          // seen[x] 表示 x 出现过
for(int i = 0; i < n; i++){
    if(nums[i] >= 1 && nums[i] <= n) seen[nums[i]] = true;
}
for(int x = 1; x <= n; x++){
    if(!seen[x]) return x;                // 第一个没出现的
}
return n + 1;
```

这个版本最好读，时间 O(n)，也没有溢出问题。但 `seen` 仍然是 O(n) 的额外空间。

## 4. 把标记数组“藏”进 nums 自己（动画第 3–6 章）

`seen` 需要 n 个位置，而 `nums` 正好有 n 个位置。办法是借用**正负号**：

> 数字 x 出现过 ⇔ 下标 x − 1 上的数是负数。

位置上原来的数还在（取绝对值就能读回来），负号额外带了一位信息，所以不用另开数组。分三步：

```cpp
int n = nums.size();

// 第一步：把没用的数（<= 0 或 > n）统一改成 n + 1，保证数组里全是正数
for(int i = 0; i < n; i++){
    if(nums[i] <= 0 || nums[i] > n) nums[i] = n + 1;
}

// 第二步：数字 cur_num 出现过，就把下标 cur_num - 1 上的数变成负数
for(int i = 0; i < n; i++){
    int cur_num = abs(nums[i]);
    if(cur_num <= n){
        nums[cur_num - 1] = -abs(nums[cur_num - 1]);
    }
}

// 第三步：第一个还是正数的下标 i，说明 i + 1 没出现过
for(int i = 0; i < n; i++){
    if(nums[i] > 0) return i + 1;
}
return n + 1;
```

三个细节（后两个对应动画第 7 章）：

1. **为什么先改成 n + 1**：负号要当标记用，数组里原有的负数和 0 会造成混淆。它们本来就和答案无关，统一换成一个超出范围的正数。
2. **读的时候为什么取 `abs`**：这个位置可能已经被别的数打过标记，变成了负数，绝对值才是它原来的值。
3. **为什么写 `-abs(...)` 而不是直接取反**：同一个数出现两次时，直接取反会把负号翻回正号，标记就丢了。

对应关系：第 3 节的 `seen[x] = true` 变成了“把 `nums[x - 1]` 变负”，`!seen[x]` 变成了“`nums[x - 1] > 0`”。

## 5. 手推 `[3, 4, -1, 1]`（动画第 4–6 章）

n = 4。第一步把 −1 改成 5，得到 `[3, 4, 5, 1]`。

| i | cur_num | 动作 | 数组 |
| --- | --- | --- | --- |
| 0 | 3 | 把下标 2 变负 | `[3, 4, -5, 1]` |
| 1 | 4 | 把下标 3 变负 | `[3, 4, -5, -1]` |
| 2 | 5（`abs(-5)`） | 大于 n，跳过 | `[3, 4, -5, -1]` |
| 3 | 1（`abs(-1)`） | 把下标 0 变负 | `[-3, 4, -5, -1]` |

第三步从左往右看：下标 0 是负数（1 出现过），下标 1 是正数，所以 2 没出现过，答案是 2。

## 6. 题解的“原地交换”怎么读

交换法的想法是给每个数安排座位：**数字 x 应该坐在下标 x − 1**。把能坐回去的数都换到自己的座位上，然后从左往右找第一个“坐的人不对”的座位。

```cpp
int n = nums.size();
for(int i = 0; i < n; i++){
    // nums[i] 是 1 到 n 里的数，并且它的座位上坐的不是它：把它换到座位上
    while(nums[i] >= 1 && nums[i] <= n && nums[nums[i] - 1] != nums[i]){
        swap(nums[i], nums[nums[i] - 1]);
    }
}
for(int i = 0; i < n; i++){
    if(nums[i] != i + 1) return i + 1;     // 座位 i 上不是 i + 1
}
return n + 1;
```

难懂的地方通常是这三处：

1. **为什么是 `while` 不是 `if`**：换完以后，位置 i 上来了一个新的数，它也可能需要送回座位，所以要接着处理，直到位置 i 上的数没法再送（不在 1 到 n 之间，或者座位上已经是同样的数）。
2. **条件为什么是 `nums[nums[i] - 1] != nums[i]`**：意思是“目标座位上还不是这个数”。如果写成 `nums[i] != i + 1`，遇到重复数字会死循环，比如 `[1, 1]`：第二个 1 的座位已经坐着 1，换来换去永远不变。
3. **两层循环为什么还是 O(n)**：每交换一次，就有一个数坐到了自己的座位上，之后不会再被换走。座位只有 n 个，所以总共最多交换 n 次。

手推 `[3, 4, -1, 1]`：

| i | 过程 | 数组 |
| --- | --- | --- |
| 0 | 3 的座位是下标 2，那里是 −1，交换；位置 0 变成 −1，不在范围内，停 | `[-1, 4, 3, 1]` |
| 1 | 4 的座位是下标 3，那里是 1，交换 | `[-1, 1, 3, 4]` |
| 1 | 位置 1 现在是 1，座位是下标 0，那里是 −1，交换；位置 1 变成 −1，停 | `[1, -1, 3, 4]` |
| 2、3 | 3 和 4 已经在自己的座位上 | `[1, -1, 3, 4]` |

下标 1 上不是 2，答案是 2。

两种写法都是时间 O(n)、额外空间 O(1)，都会修改传进来的 `nums`。标记法不移动数字，只改符号，读起来更直接；交换法是题解里更常见的写法，面试时能讲清上面三点就可以。

## 7. 易错点

- 标记法漏掉第一步：原有的负数会被当成标记。
- 标记法读数时忘了 `abs`。
- 标记法直接取反：重复数字会把标记翻掉，例如 `[1, 1]`。
- 交换法的 `while` 条件写成 `nums[i] != i + 1`：重复数字时死循环。
- 交换法手写三行交换时，下标要先存起来：`nums[i]` 被改掉以后，`nums[nums[i] - 1]` 指的就不是原来的位置了。用 `swap` 没有这个问题。
