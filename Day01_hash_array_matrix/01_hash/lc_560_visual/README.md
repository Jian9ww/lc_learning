## 记号

- 动画用 0 起始下标，`P[j]` 表示 `nums[0..j]` 的和。`P[-1] = 0` 表示空前缀（一个数都没取），是数学约定，不是在 C++ 里访问负下标。
- 也常见另一种写法：`prefix[t]` 表示前 t 个数的和，`prefix[0] = 0`。两者的关系是 `P[j] = prefix[j + 1]`。
- 任意一段的和：`nums[i..j] = P[j] − P[i−1] = prefix[j+1] − prefix[i]`。
- 源码优化版里的 `temp_sum`：处理完下标 i 后，等于 `P[i]`。

## 1. 原来的写法：固定起点，向后累加（第 2 章）

```cpp
// lc_560.cpp 注释中保存的原始解法（摘录）
for(int i = 0; i < n; i++){
    int temp_sum = 0;
    int j = i;
    while(j < n){
        temp_sum += nums[j];
        j++;
        if(temp_sum == k)
            count++;
    }
}
```

每换一个起点 i，`temp_sum` 清零，从 i 一路加到末尾，每个终点判断一次。6 个数共 6×7/2 = 21 格，n 个数就是 n(n+1)/2 格，时间 O(n²)，额外空间 O(1)。21 格里只有 6 格是答案。

## 2. 重复在哪（第 3 章）

把暴力表格按列对齐：第 1 行的每一格，都等于正上方第 0 行的数减去 `nums[0]`；第 2 行等于第 0 行减去 `nums[0] + nums[1]`。第 0 行本身就是前缀和 P。

```text
sum(i..j) = P[j] − P[i−1]
```

每一行都从头重新累加，是在重复计算第 0 行已经算过的东西。只要记住前缀和，任意一段的和都能用两个前缀和相减得到。

## 3. 换个方向：固定终点，往左找起点（第 4 章）

站在终点 j，问：有多少个起点 i，使 `P[j] − P[i−1] = k`？等价于：

```text
j 之前，有多少个前缀和等于 P[j] − k ？
```

画成折线更直观：前缀和是高度，子数组和是两点的高度差。站在 j = 4（高度 4）要找和为 3 的段，就往左找高度为 1 的点；P[0] 和 P[2] 都是 1，所以一下找到 2 段。

这就是 LC1 两数之和的查找动作：LC1 在 j 处查补数 `target - nums[j]`，这里查 `P[j] − k`。区别在于 LC1 找到一个就返回，这里要数出所有起点，所以表里存的是次数，不是下标。

## 4. 哈希表存什么，为什么能替代内层循环（第 5、6 章）

`freq` 存“前缀和 → 到目前为止出现了几次”。查一次 `freq` 就知道以 j 结尾、和为 k 的子数组有几个。暴力表格里第 j 列就是所有以 j 结尾的子数组；暴力法把这一列逐格算出来，哈希表一次就数完整列。

```cpp
// lc_560.cpp 优化版
int subarraySum(vector<int>& nums, int k) {
    int n = nums.size();
    int count = 0;
    int temp_sum = 0;  // 当前前缀和：nums[0] + ... + nums[i]
    unordered_map<int, int> freq;  // 前缀和 -> 之前出现的次数
    freq[0] = 1;  // 数组开始前的空前缀，使从下标 0 开始的子数组也能被统计

    for(int i = 0; i < n; i++){
        temp_sum += nums[i];

        // 当前前缀和 - 之前的前缀和 = k
        // 因此查找之前有多少个前缀和等于 temp_sum - k。
        auto it = freq.find(temp_sum - k);
        if(it != freq.end()){
            count += it->second;
        }

        // 先查询、再记录当前前缀，避免 k == 0 时把空子数组算进去。
        freq[temp_sum]++;
    }
    return count;
}
```

两个版本都有 `temp_sum`，含义不同：原版是从起点 i 开始的区间和，每换一行清零；优化版从数组开头一直累加，是前缀和。

动画第 9 章把这一步写成 `count += freq[P[j] − k];`，那是示意。用 `[]` 也能算对（缺的键读出 0），但每次查不到都会往表里插入一个值为 0 的键，表会越变越大。源码用 `find`，查不到时不插入，原因见 [note E.3 unordered_map](../../../note.md#ch-e) 的“返回值和副作用”。

## 5. 手推一遍（对照第 5 章）

开始时 `freq = {0: 1}`。每一行先查询，再把当前 `temp_sum` 的次数加一。

| i | nums[i] | temp_sum | 查 temp_sum − 3 | 查到几个 | 对应的子数组 | count | 记录后的 freq |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 0 | 1 | 1 | −2 | 0 | — | 0 | {0:1, 1:1} |
| 1 | 2 | 3 | 0 | 1 | nums[0..1] | 1 | {0:1, 1:1, 3:1} |
| 2 | −2 | 1 | −2 | 0 | — | 1 | {0:1, 1:2, 3:1} |
| 3 | 2 | 3 | 0 | 1 | nums[0..3] | 2 | {0:1, 1:2, 3:2} |
| 4 | 1 | 4 | 1 | 2 | nums[1..4]、nums[3..4] | 4 | {0:1, 1:2, 3:2, 4:1} |
| 5 | 2 | 6 | 3 | 2 | nums[2..5]、nums[4..5] | 6 | {0:1, 1:2, 3:2, 4:1, 6:1} |

6 次查表得到 6，和暴力枚举 21 格的结果一样。

## 6. 两个细节，外加一个（第 7 章）

1. **`freq[0] = 1`**：代表空前缀 `P[-1] = 0`。从下标 0 开始的子数组（上表的 nums[0..1]、nums[0..3]）左边没有真实的前缀，只能对上它。去掉这一行，答案变成 4。
2. **先查询，再记录**：看 `nums = [1]`、`k = 0`，正确答案 0。如果先把当前 `temp_sum = 1` 记进表，再查 `1 − 0 = 1`，就会找到自己，等于数了一段空数组，答案变成 1。
3. **加次数，不是加 1**：相同的前缀和出现几次，就对应几个不同的起点。上表 i = 4 时，P[0] 和 P[2] 都是 1，一次加 2。只用 set 记“出现过”会漏算：`{0, 0}`、`k = 0` 的答案是 3（[0]、[1]、[0..1]），只加 1 会得到 2。

## 7. 代价与适用范围（第 8 章）

- 空间：多了一张哈希表，额外空间从 O(1) 变成 O(n)。
- 时间：O(n²) 变成平均 O(n)。n = 20000 时，约两亿次加法变成两万次查表。哈希严重冲突时单次查找会退化，最坏仍可能是 O(n²)。
- 数组里有负数，“和变大就收缩窗口”的滑动窗口不成立；前缀和的做法不受正负影响。
- 数值范围：前缀和绝对值不超过 2×10⁴ × 1000 = 2×10⁷，答案最多 n(n+1)/2 ≈ 2×10⁸，都在 `int` 范围内。

## 一句话（第 9 章）

固定右端点，一次查表数完所有左端点：内层循环变成一次哈希查询，O(n²) 变成 O(n)。
