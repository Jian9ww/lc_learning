## 做完一题更新哪里

1. 代码存到所在章节目录，文件名 `lc_<题号>.cpp`。
2. [学习路线.md](学习路线.md)：勾选这道题；原站没有逐题列出的章节，先加一行再勾选。
3. [note.md](note.md)：在方法篇本章的题目表加一行（如 1.1.7）；用到新的 API，补到基础篇对应的一章（已有的就补一句，不另写一份）。

- 看不懂的题：请 AI 写讲解，放在题目代码旁边（有图用 `lc_<题号>_visual/`，只有文字用 `lc_<题号>.md`），再从方法表链接过去。讲解的网页版动画（`.html`）和文字进 Git；视频和动图（`*.mp4`、`*.gif`）只留在本地。
- 做完一章：补完 note 里这一章的方法归纳，再把学习路线里的“当前”改到下一章。
- 做完一个 Day：在 note 方法篇这一章的标题下面写一段小结（例子见第 1 章）。

## 约定

### 写代码

- 目录和源码文件名只用英文：工具链遇到中文路径出现过乱码和 `Illegal byte sequence` 错误。中文可以写在注释、输出和文档里。
- 题目文件叫 `lc_<题号>.cpp`，AI 题用算法名，如 `knn.cpp`。每个文件有自己的 `main()`，算法写成独立函数；需要保存样例时用同名的 `.in` / `.out`。
- 原站支持 C++ 的题就在原站提交；不支持的（目前 AI 题都不支持）在本地用 C++14 运行，核对样例和边界。
- 章节目录里的 `.gitkeep` 只是让 Git 保留还没放代码的目录，放入代码后可以删掉。

### 与 AI 协作

- 从我的代码和思路出发讲解：先说清原来的思路，再一步步推导优化。
- 优化或纠错时保留我的原解法：原解法完整注释后放在上方，新版本写在下方，说明每个主要变化，尽量沿用原来的变量和结构。
- 题目是否完成由我确认后在学习路线勾选；note 的自查项也由我自己勾选。
- 不自动提交或推送。

### 两台电脑同步

- 开始前：工作区没有未处理的改动时，执行 `git pull --ff-only`。
- 换电脑前：用 `git status` 检查，提交本次改动后 `git push`；另一台电脑先拉取再继续。

### 编译、运行、调试

根目录的 `.vscode` 配置对所有子目录生效，不需要复制。保存并打开要操作的 `.cpp`：

- `Ctrl+Shift+B`：以 C++14 编译当前文件。
- `F5`：编译并调试当前文件，断点打在当前源码里。
- 终端 → 运行任务 → `C++14: Run active file`：编译并运行，在终端输入数据。

`.exe` 生成在源码旁边，已被 `.gitignore` 忽略。编译器是 MSYS2 UCRT64 的 `C:/msys64/ucrt64/bin/g++.exe`，参数包含 `-std=c++14 -Wall -Wextra`。
